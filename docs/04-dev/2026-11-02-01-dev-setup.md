# 개발 준비

5단계(기능 단위 개발)에 들어가기 전에 갖출 도구·기반 코드·규약을 정한 문서다. **정본**이다. 5단계 기능 순서는 `2026-11-02-02-implementation-plan.md`.

- 입력: 데이터 아키텍처(`docs/03-data/2026-11-02-01-data-architecture.md`), 디자인 토큰(`docs/02-screens/2026-11-02-02-design-tokens.md`), 화면 명세·와이어프레임(`docs/02-screens/`)
- 진행 상태는 7장 체크리스트로 관리한다

## 1. 결정 요약

| #   | 항목           | 결정                                                                                                                                         |
| --- | -------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| P1  | git hook       | lefthook                                                                                                                                     |
| P2  | DB 통합 테스트 | 로컬 Docker Postgres. CI는 GitHub Actions Postgres 서비스                                                                                    |
| P3  | E2E 로그인     | 테스트 환경에서만 켜지는 테스트 로그인 경로. 운영 빌드에서는 경로가 없다                                                                     |
| P4  | Zustand        | 지금은 넣지 않는다. 서버 상태는 TanStack Query, 화면 상태는 URL. 필요해지면 그때 추가                                                        |
| P5  | Tenada         | `next/font/local`로 직접 배포 (`src/assets/fonts/`). 넣기 전에 라이선스(웹 배포·재배포 허용)를 확인한다. 로그인 소개 문구는 Noto Sans KR 700 |
| P6  | E2E 실행 시점  | 로컬과 PR에서만. 매 푸시 CI에서는 돌리지 않는다                                                                                              |

버전: Next.js 16, React 19, TS 6, Node 24, pnpm 10, ESLint 10, Vitest 5 (CLAUDE.md의 버전 규칙).

## 2. 개발 도구

### 2-1. 스크립트 (`package.json`)

| 스크립트                  | 명령                                            | 비고                                |
| ------------------------- | ----------------------------------------------- | ----------------------------------- |
| `dev`                     | `next dev`                                      |                                     |
| `build`                   | `next build`                                    |                                     |
| `lint`                    | `eslint .`                                      | `next lint`는 Next 16에서 삭제됨    |
| `format` / `format:check` | `prettier --write .` / `prettier --check .`     |                                     |
| `typecheck`               | `tsc --noEmit`                                  |                                     |
| `test`                    | `vitest run --project unit --project component` | 단위·컴포넌트                       |
| `test:db`                 | `vitest run --project db`                       | DB 통합 (Docker Postgres 필요)      |
| `test:e2e`                | `playwright test --pass-with-no-tests`          |                                     |
| `db:up` / `db:down`       | `docker compose up -d db` / `down`              | 테스트용 Postgres                   |
| `db:migrate` / `db:seed`  | `prisma migrate dev` / seed 스크립트            |                                     |
| `check:wireframes`        | `python3 scripts/check-wireframes.py`           | 기존 점검 스크립트                  |
| `check:tokens`            | `python3 scripts/check-tokens.py`               | 토큰 문서 ↔ `globals.css`·견본 html |

### 2-2. 포맷·린트·타입

- **Prettier 3**: `prettier-plugin-tailwindcss`(설치돼 있음)로 클래스 순서를 정리한다. `.prettierignore`에 `docs/**/*.html`, `docs/reference/`, `public/`, `pnpm-lock.yaml`, `src/generated/`.
- **ESLint 10**: flat config로 `eslint-config-next`의 `core-web-vitals`·`typescript`를 쓰고, `eslint-config-prettier`로 포맷 규칙 충돌을 끈다.
- **TypeScript**: strict는 이미 켜져 있다. `noUncheckedIndexedAccess`를 추가한다.

### 2-3. 테스트

| 층       | 도구                                   | 대상                                                                                                                 | 위치                         |
| -------- | -------------------------------------- | -------------------------------------------------------------------------------------------------------------------- | ---------------------------- |
| 단위     | Vitest 5                               | 반복 기록 규칙(생성·수정·삭제·연장), 날짜·말일 맞추기, 검증 스키마, 금액 축약, 계산기, 제목 추천 거르기(앞부분·초성) | 대상 파일 옆 `*.test.ts`     |
| 컴포넌트 | Vitest + Testing Library (jsdom)       | 공통 컴포넌트 상태(CG), 폼 검증 표시                                                                                 | `*.test.tsx`                 |
| DB 통합  | Vitest `db` 프로젝트 + Docker Postgres | API 핸들러·쿼리·트랜잭션 (범위 수정·연장·탈퇴·소유권 404)                                                            | `src/server/**/*.db.test.ts` |
| E2E      | Playwright 1                           | 핵심 흐름: 로그인 → 등록 → 달력 반영, 반복 범위 수정, 탈퇴                                                           | `e2e/`                       |

- 반복 규칙 단위 테스트는 3단계 견본(`docs/03-data/2026-11-02-02-recurring-scenarios.html`)의 경우를 하나씩 옮긴다. 견본의 시뮬레이터와 실제 코드가 같은 결과를 내야 한다.
- DB 통합 테스트는 실행할 때마다 로컬 `mdiary_test`의 스키마를 비우고 마이그레이션을 다시 적용한다 (`vitest.db-setup.ts`). 로컬 테스트 DB가 아니면 지우지 않는다.
- 테스트 로그인(P3): `E2E_TEST_LOGIN=1`이고 운영이 아닐 때만 `/api/test/login`을 연다. 운영 빌드에서는 경로 자체를 만들지 않는다.

### 2-4. git hook (lefthook)

| 시점       | 실행                                                                                                                                         |
| ---------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| pre-commit | 바뀐 파일만: Prettier 확인, ESLint. `docs/02-screens/**`가 바뀌었으면 와이어프레임 점검, 토큰 문서·견본·`globals.css`가 바뀌었으면 토큰 점검 |
| pre-push   | `typecheck`, `test`                                                                                                                          |

### 2-5. Claude Code hook (`.claude/settings.json`)

| 이벤트                      | 동작                                                                                             |
| --------------------------- | ------------------------------------------------------------------------------------------------ |
| 파일 수정 직후 (Edit·Write) | 고친 파일을 Prettier로 정리한다 (`.prettierignore` 제외)                                         |
| 파일 수정 직후              | `docs/02-screens/**`를 고쳤으면 와이어프레임 점검을 돌리고 결과(통과·실패)를 Claude에게 돌려준다 |
| 파일 수정 직후              | 토큰 문서·견본·`globals.css`를 고쳤으면 토큰 점검을 돌리고 결과를 Claude에게 돌려준다            |

기존 `permissions.ask`(commit·push·merge·rebase·reset)는 그대로 둔다.

### 2-6. CI (GitHub Actions)

- 트리거: `renewal-main` 푸시, PR
- 순서: pnpm install → `lint` → `format:check` → `typecheck` → `test` → `test:db`(Postgres 서비스) → `build` → `check:wireframes` → `check:tokens`
- E2E는 PR에서만 (P6)
- 비밀값이 필요한 단계는 두지 않는다. 빌드는 더미 환경 변수로 통과시킨다

## 3. 기반 코드

### 3-1. 폴더 구조

```
src/
  app/                 라우트 (페이지, Route Handlers)
    api/**/route.ts
  features/<기능>/      화면 컴포넌트·훅·쿼리 키 (calendar, expense, category, search, settings, auth)
  components/          공통 컴포넌트 (와이어프레임 CG)
  server/              서비스·쿼리·트랜잭션 (DB 접근은 여기서만)
  lib/                 db, auth, 날짜, 금액 형식 등 도구
  shared/              서버·클라이언트 공용: zod 스키마, 카테고리 목록, 정책값
  assets/              아이콘 SVG (svgr로 컴포넌트로 불러온다)
  env.ts               환경 변수 검증
prisma/
  schema.prisma, migrations/, seed.ts
scripts/
  check-wireframes.py, migrate-legacy/ (F11)
e2e/
```

### 3-2. 환경 변수

`src/env.ts`에서 zod로 검증한다. 빠지면 서버가 뜨지 않는다. 이름은 데이터 아키텍처 2장 (`DATABASE_URL`, `DIRECT_URL`, `BETTER_AUTH_SECRET`, `BETTER_AUTH_URL`, `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `CRON_SECRET`) + 테스트용 `E2E_TEST_LOGIN`. `.env.example`에 이름만 적어 커밋한다.

### 3-3. DB

- Prisma 7 + `@prisma/adapter-pg`. 앱은 Neon(`DATABASE_URL`), 테스트는 Docker Postgres에 같은 방식으로 붙는다.
- Prisma CLI가 붙는 DB는 `DB_TARGET`으로 고른다 (`prisma/db-url.ts`): 없으면 Neon development(`DIRECT_URL`), `local`이면 Docker `mdiary_dev`, `test`면 Docker `mdiary_test`.
- 마이그레이션은 로컬에서 만들고(`pnpm db:migrate`), Neon development에는 `pnpm db:deploy`로 적용한다.
- 첫 마이그레이션: 데이터 아키텍처 7장 스키마 + CHECK 제약 SQL.
- `docker-compose.yml`: Postgres 18 하나에 `mdiary_dev`(마이그레이션 작성)·`mdiary_test`(DB 테스트). Neon과 같은 메이저 버전을 쓴다.
- seed: SC-03① 10월 달력 기준으로 개발 데이터를 넣는다 (10월 42건 1,234,500원, 8월 812,000원, 넷플릭스·월세 정기 계속, 아이패드 할부). 주인은 테스트 사용자 `test@mdiary.local`(P3와 같은 사용자).

### 3-4. 인증

- Better Auth + Prisma 어댑터 + Google 제공자. 테이블은 Better Auth CLI가 만드는 정의를 스키마에 붙인다.
- `src/proxy.ts`(Next 16의 middleware): 세션이 없으면 `/login?next=…`로 보낸다 (화면 명세 RT). API는 401.

### 3-5. 디자인 토큰·글꼴·아이콘

- 토큰 문서의 색(라이트·다크), 글자 크기(짝수), 간격, 모서리(6·8·14·20·full), 그림자를 `src/app/globals.css`의 Tailwind 4 `@theme` 변수로 옮긴다. 다크는 `data-theme`와 시스템 설정 둘 다 따른다 (SC-10 화면 모드).
- 글꼴: Noto Sans KR·Rubik은 `next/font/google`, Tenada는 `next/font/local` (P5).
- 아이콘: `src/assets/*.svg`를 svgr로 불러온다. 모두 `currentColor`라 글자색을 따른다.
- 토큰 점검: 토큰 문서와 `@theme` 값을 비교하는 `scripts/check-tokens.py`를 만들고, lefthook pre-commit과 CI에 연결한다.

## 4. 코드 규약

- 날짜는 `YYYY-MM-DD` 문자열로 다룬다. JS `Date`로 바꾸는 곳은 `src/lib/date`의 함수뿐 (데이터 아키텍처 3-1).
- DB 접근은 `src/server`에서만. Route Handler는 검증 → 세션 → 서비스 호출 → 응답만 한다.
- 검증 스키마는 `src/shared`에 두고 서버·클라이언트가 같이 쓴다.
- 화면 문구는 합니다체 초안. 사용자가 검토한다.
- 커밋은 사용자 요청 시에만, 한국어 메시지, AI 작성자 표시 없음 (CLAUDE.md).
