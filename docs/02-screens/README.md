# 화면 문서 작성 규칙

`docs/02-screens/`의 기능 명세와 와이어프레임을 쓰고 고칠 때 따르는 규칙이다.
세션이 바뀌어도 이 문서와 점검 스크립트로 같은 기준을 지킨다.

## 1. 문서와 정본

| 문서                | 역할                                             |
| ------------------- | ------------------------------------------------ |
| `*-page-spec.md`    | 화면 기능 명세. **정본**이다                     |
| `*-wireframes.html` | 화면설계서(와이어프레임). 명세를 화면으로 옮긴다 |

- 서술이 어긋나면 명세가 이긴다. 와이어프레임에서 내린 화면 결정은 명세에도 반영한다.
- 사용자가 명세의 문구를 직접 고치면 와이어프레임의 같은 문구도 맞춘다.
- 화면 ID(SC-xx)는 두 문서가 같이 쓴다. CG(공통 컴포넌트)·RT(라우팅)·CM(공통 상태)은 와이어프레임에만 있는 공통 절이다.

## 2. 화면 블록 구성

화면 블록 하나 = 제목줄(화면 ID, 이름, 명세 위치) → 진입 설명 → 캔버스(프레임들) → 명세표.

- **프레임**: 상태 하나를 그린 휴대폰 화면. 라벨은 `종류 + ①②… + 상태 이름`.
  - 종류: `STATE` 정상 · `SHEET` 바텀시트 · `DIALOG` 확인 다이얼로그 · `ERROR` 오류·알림 · `LOADING` 로딩 · `EMPTY` 빈 상태
- **한 프레임에는 한 가지 상태만** 그린다. 모달·바텀시트·오류·알림은 경우마다 따로 프레임을 만든다.
- **명세표**: `No · 요소 · 명세`. 버튼·입력·드롭다운처럼 조작하는 요소는 상태 블록(기본 상태 · 활성 조건 · 비활성 조건)을 단다.

## 3. 그리기 규칙

1. **프레임 안에는 실제 화면에 보이는 요소만 그린다.** 상태 설명은 프레임 아래 설명 캡션(`.fr-note`, ※)이나 명세표에 쓴다.
2. **빗금(`.omit`)은 UI가 아닌 영역에만 쓴다.**
   - 생략한 영역 (예: "생략: 달력")
   - 실제로는 보이지 않지만 설명을 위해 표시해야 하는 영역: 인터랙션으로 가려지거나 화면 밖에 있는 영역, 안전 여백, 평소 비어 있는 자리, 기기 키보드
   - 그 상태를 설명하는 핵심 요소는 생략하지 않는다. 예: "다른 달로 이동" 상태는 그 달 달력 전체(앞뒤 달 날짜 포함)를 그린다.
3. **회색 박스(스켈레톤, `.skel`)는 로딩 상태에만 쓴다.** 생략을 회색 박스로 그리지 않는다.
4. **번호(콜아웃)는 설명하는 요소에 직접 붙인다.** 범례 줄을 따로 만들어 번호를 모아 두지 않는다.
5. **명세표에 적은 상태·문구는 반드시 어느 프레임엔가 그린다.** 그리지 않을 때는 명세표에 "그림 생략"이라고 적는다.
6. **예시 데이터는 실제와 맞춘다.** 날짜와 요일은 실제 달력과 일치해야 한다. 같은 예시가 여러 프레임에 나오면 금액·건수를 같게 쓴다 (그래프의 합과 목록 요약의 합, 칸 금액의 합과 월 합계 등).

## 4. 문구

- 화면 문구는 합니다체. 명세 서술은 한다체.
- 문구는 모두 **초안**이다. 사용자가 직접 검토한다. 명세표에서는 문구를 파란색(`.cp`)으로 표시해 찾기 쉽게 한다.

## 5. 결정과 변경 기록

- 정해야 할 제약사항(글자 수, 문자 패턴, 활성화 기준, 오류 대응 등)은 빠짐없이 모아 사용자와 정한다. 정하기 전에는 `D-xx` 표시를 달고, 정해지면 본문과 명세에 반영한 뒤 표시를 지운다.
- 이미 정한 결정이 바뀌면 그 의사결정 기록을 남길지 사용자에게 묻는다. 결정 번복 일자를 본문에 남기지 않는다.
- 와이어프레임 맨 아래 **변경 이력**에 리뷰 사이클마다 무엇을 고쳤는지 포괄적으로 남긴다.

## 6. 점검

와이어프레임이나 명세를 고친 뒤에는 반드시 돌리고, 결과를 보고에 포함한다.

```bash
python3 scripts/check-wireframes.py
```

| 점검                | 내용                                                                              |
| ------------------- | --------------------------------------------------------------------------------- |
| 번호 싱크           | 블록마다 콜아웃 번호와 명세표 번호가 1부터 빠짐없이 1:1로 맞는지                  |
| 프레임 안 설명·생략 | 빗금·설명 캡션 밖에 괄호로 시작하는 문장, "생략", "…", "꼴", 한다체 문장이 있는지 |
| 스켈레톤 오용       | 로딩이 아닌 프레임에서 `.skel`을 쓰는지                                           |
| 프레임 참조         | 명세표가 가리키는 ①②…가 그 블록에 실제로 있는지 (다른 블록 참조 "CG ⑨" 등은 제외) |
| 요일                | `2026년 10월 18일 (일)` 꼴 날짜의 요일이 맞는지 (와이어프레임과 이 폴더의 md)     |

스크립트가 보지 못하는 것은 직접 확인한다.

- 번호가 설명하는 요소 옆에 붙어 있는지
- 그림과 명세표 내용이 맞는지 (규칙 5, 6)
- 고친 블록이 브라우저에서 깨지지 않는지: 스크린샷으로 확인한다

```bash
"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --headless=new --hide-scrollbars \
  --window-size=1440,14000 --screenshot=shot.png "file://$PWD/docs/02-screens/<와이어프레임>.html"
```
