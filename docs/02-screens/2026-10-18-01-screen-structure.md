# 화면 구성안: 화면 목록과 이동 구조

> 2단계 산출물 (초안). 기획은 `../01-product/2026-10-17-02-product-brief.md` 참고.
> 상태: 결정 완료 (2026-10-18), 사용자 리뷰 대기.

## 1. 범위

이 문서는 화면 목록, 화면 간 이동, 화면별 구성 요소와 상태(비어 있음·로딩·오류)를 다룬다.
와이어프레임과 디자인 토큰은 이 문서가 확정된 뒤 별도 문서로 만든다.

**인증과의 경계**
- 이 문서에서 정하는 것: 로그인 화면, 로그인하지 않은 사용자가 보호된 화면에 들어왔을 때의 동작, 로그아웃과 회원 탈퇴의 위치·확인 절차, 세션이 만료됐을 때 사용자에게 보이는 동작
- 3단계(데이터 아키텍처)에서 정하는 것: 인증 라이브러리(Auth.js, Better Auth 등), 세션 저장 방식, 사용자 테이블 구조

## 2. 화면 목록

| 경로 | 화면 | 로그인 필요 | 비고 |
|---|---|---|---|
| `/login` | 로그인 | 아니오 | 로그인한 상태로 들어오면 `/`로 보낸다 |
| `/` | 월간 달력 (메인) | 예 | `?month=2026-10&date=2026-10-18` |
| `/categories` | 카테고리별 | 예 | `?from=2026-10&to=2026-10&category=food` |
| `/search` | 검색 | 예 | `?q=쿠팡` |
| `/expenses/new` | 지출 등록 | 예 | `?date=2026-10-18` (달력에서 고른 날짜) |
| (바텀시트) | 지출 상세 | 예 | 목록 화면 위에 연다. `?expense=id` |
| `/expenses/[id]/edit` | 지출 수정 | 예 | 등록 화면과 같은 폼을 쓴다 |
| `/settings` | 설정 | 예 | 로그아웃, 회원 탈퇴 |

- 조회 조건(월, 기간, 카테고리, 선택한 날짜, 검색어)은 URL 쿼리에 둔다. 새로고침하거나 뒤로 가도 보던 화면이 유지되고, 홈 화면에 설치한 PWA에서도 같은 방식으로 동작한다.
- 쿼리가 없으면 오늘 기준 기본값을 쓴다.

## 3. 내비게이션

**하단 탭 바, 등록 버튼은 탭 바 중앙** (결정, 2026-10-18). 떠 있는 버튼은 두지 않는다.

탭 구성 (결정): 달력 / 카테고리 / ＋(등록) / 검색 / 설정.

```
┌──────────────────────────────────┐
│            (화면 내용)             │
├──────┬──────┬──────┬──────┬──────┤
│ 달력  │카테고리│  ＋  │ 검색  │ 설정  │
└──────┴──────┴──────┴──────┴──────┘
```

- 구버전은 상단에 메뉴 5개를 뒀다. 모바일 한 손 조작을 고려해 하단 탭으로 바꾼다.
- 등록·수정 화면에서는 탭 바를 숨기고 상단에 뒤로 가기를 둔다.
- 등록 버튼은 달력에서 날짜를 골랐으면 그 날짜, 아니면 오늘 날짜로 등록 화면을 연다.

## 4. 화면별 구성

### 4-1. 로그인 `/login`

- 서비스 이름, 한 줄 소개("내가 얼마 썼는지만 알고 싶을 때"), Google 로그인 버튼
- 보호된 화면에서 넘어왔으면 로그인 후 원래 화면으로 돌아간다 (예: `/login?next=/categories`).
- 오류: 로그인 취소·실패 시 버튼 아래에 안내 문구를 보여준다.

### 4-2. 월간 달력 `/` (메인)

| 영역 | 구성 |
|---|---|
| 상단 | 연·월 표시(누르면 연·월 선택), 이전·다음 달 버튼, 월 합계 |
| 달력 | 날짜별 지출 합계, 오늘 표시, 선택한 날짜 강조 |
| 하단 목록 | 선택한 날짜의 내역 (카테고리 아이콘, 제목, 금액, 정기·할부 표시), 그날 합계 |

- 기본 상태: 이번 달, 오늘 날짜 선택
- **날짜 칸 금액 표시** (결정): 칸에 다 들어가면 전체 금액을 보여주고, 넘칠 때만 줄여서 보여준다 (예: 123,400 → 12.3만).
- 비어 있음: 내역이 없는 날은 "기록이 없어요" + 이 날짜로 등록하기 버튼
- 연도 선택 범위: 구버전은 최근 5년으로 제한했다. 리뉴얼은 가장 오래된 기록이 있는 해부터 올해(+1년, 정기지출 확인용)까지 고른다.
- **월 이동 스와이프** (결정): 달력 영역을 왼쪽으로 밀면 다음 달, 오른쪽으로 밀면 지난달. 미는 동안 이번 달과 옆 달이 손가락을 따라 움직이고, 화면 폭의 약 1/4 이상 밀거나 빠르게 튕기면 넘어가며, 덜 밀면 제자리로 돌아온다. 위아래 스크롤은 그대로 동작한다.

### 4-3. 카테고리별 `/categories`

| 영역 | 구성 |
|---|---|
| 기간 | 기본은 오늘이 속한 달의 1일~말일. **시작 연·월 ~ 끝 연·월**로 바꿀 수 있다. 최대 5년 |
| 요약 | 기간 합계 |
| 비중 그래프 | **가로 막대 그래프** (결정). 기간 합계 안에서 카테고리별 비중. 비중 큰 순서로 한 줄씩 막대, %, 금액 |
| 카테고리 필터 | 전체 + 10개. 그래프의 줄을 눌러도 필터가 바뀐다 |
| 내역 목록 | 목록 상단 드롭다운으로 정렬: **최신순**(기본) / **큰 금액순**. 필터를 고르면 그 카테고리의 합계를 함께 보여준다 |

- 예: 기간을 2025년 11월 ~ 2026년 10월(12개월)로 고르면, 그 12개월 총지출 안에서 각 카테고리가 차지하는 비중을 보여준다.
- 이전 기간과의 증감 비교는 하지 않는다 (결정).
- 지출이 없는 카테고리는 그래프에서 뺀다.
- 비어 있음: 기간에 내역이 없으면 그래프 대신 안내 문구.

### 4-4. 검색 `/search`

- 검색어 입력, 결과 목록(날짜 내림차순, 월별로 묶음, 결과 건수와 합계)
- 결과를 누르면 상세 바텀시트
- 검색 대상 (결정): 제목 + 내용. 계산식이나 메모로도 찾을 수 있다.
- 비어 있음: 검색 전에는 최근 검색어 또는 안내 문구, 결과가 없으면 "찾는 기록이 없어요"

### 4-5. 지출 등록 `/expenses/new` · 수정 `/expenses/[id]/edit`

| 필드 | 입력 방식 |
|---|---|
| 날짜 | 기본값: 달력에서 고른 날짜, 없으면 오늘 |
| 제목 | 텍스트 (25자). **자주 쓴 제목 추천** (5장) |
| 카테고리 | 10개 아이콘 그리드에서 하나 선택 |
| 금액 | 숫자 키패드, 천 단위 쉼표. 옆에 계산 버튼 |
| 내용 | 선택, 200자 |
| 반복 | 없음 / 정기지출 / 할부 (6장) |

- **계산 기능**: 바텀시트로 연다. 더하기·빼기·곱하기·1/n, 끝전 처리 선택, "적용"하면 금액에 결과를 넣고 계산식을 내용에 붙인다.
- 저장 후: 그 날짜가 선택된 월간 달력으로 돌아간다.
- 오류: 필수값 누락은 필드 아래에 표시한다 (구버전의 결과 모달 대신). 저장 실패는 토스트로 알리고 입력값은 유지한다.

### 4-6. 지출 상세 (바텀시트)

**상세는 바텀시트, 등록·수정은 페이지** (결정, 2026-10-18).

- 달력·카테고리·검색 목록에서 항목을 누르면 그 화면 위에 연다.
- URL 쿼리(`?expense=id`)로 열어서 뒤로 가기로 닫힌다.
- 날짜, 제목, 카테고리, 금액, 내용, 정기·할부 정보(회차 3/12, 다음 결제일)
- 수정(→ 수정 페이지), 삭제 버튼. 정기·할부 건이면 수정·삭제 시 적용 범위를 고른다 (6장).
- 삭제는 확인 단계를 거친다.

### 4-7. 설정 `/settings`

- 로그인한 계정(Google 이메일)
- 화면 모드: 시스템 설정 따름 / 라이트 / 다크
- 로그아웃
- 회원 탈퇴: 삭제될 내용(계정과 지출 기록 N건)을 보여주고, 한 번 더 확인받는다.
- (MVP 이후) CSV 내보내기 자리

### 4-8. 공통 상태

| 상태 | 처리 |
|---|---|
| 로딩 | 첫 로딩은 화면 모양의 스켈레톤. 월 이동처럼 다시 불러올 때는 이전 데이터를 유지한 채 갱신 |
| 오류 | 조회 실패는 화면 안에 다시 시도 버튼. 저장 실패는 토스트 |
| 세션 만료 | 다음 요청에서 로그인 화면으로 보내고, 로그인 후 원래 화면으로 돌아온다 |
| 오프라인 | 기록 불가 안내 배너 (오프라인 기록은 지원하지 않음) |
| 다크 모드 | 모든 화면을 라이트·다크 두 벌로 만든다. 디자인 토큰 단계에서 색을 두 벌로 정의한다 |

## 5. 자주 쓴 제목 추천

**요청**: 같은 제목을 2번 이상 입력한 적이 있으면, 제목을 입력할 때 연관검색어처럼 보여준다 (예: "쿠" → "쿠팡").

| 항목 | 결정 (2026-10-18) |
|---|---|
| 구현 방식 | 등록·수정 화면에 들어올 때 "2번 이상 쓴 제목 + 사용 횟수 + 마지막 사용일 + 마지막 카테고리" 목록을 한 번 받아 오고, 입력할 때마다 화면 안에서 거른다. 입력 중에는 서버 요청이 없다 |
| 대상 | 2번 이상 쓴 제목 |
| 매칭 | 앞부분 일치 + 초성 검색 ("쿠" → 쿠팡, "ㅋㅍ" → 쿠팡). 한글을 자모로 분해해서 비교해, 치는 도중("쿺")에도 추천이 끊기지 않는다 |
| 개수·순서 | 최대 5개. 사용 횟수가 많은 순, 같으면 최근에 쓴 순 |
| 골랐을 때 | 제목과 그 제목에 마지막으로 쓴 카테고리를 채운다. 카테고리는 다시 고를 수 있다 |

검토한 다른 방식:
- 입력할 때마다 서버 검색: 요청이 많고 네트워크 지연이 그대로 보인다. 1인 사용 규모에서는 이점이 없다.
- 제목을 별도 테이블로 관리: 수정·삭제 때 횟수를 맞춰야 해서 지금 규모에는 과하다.

> 자모 분해·초성 비교 라이브러리(`es-hangul` 등)는 4단계 개발 준비에서 정한다. 목록 조회 쿼리는 3단계에서 정한다.

## 6. 정기지출·할부 입력

| 화면 | 입력 |
|---|---|
| 등록 | 반복: 정기지출 선택 → 결제일(기본값: 선택한 날짜의 일) → 범위: 이후 계속 / 이 건부터 N개월 |
| 등록 | 반복: 할부 선택 → 총 회차(2~36), 금액은 "회차당 금액" 또는 "총액" 중 입력 |
| 수정·삭제 | 범위: 이번 건만 / 이후 전체 / 이 건부터 N개월 |

- **기간 지정은 "이 건부터 N개월"로 통일** (결정). 화면에 "2026년 10월 ~ 2027년 3월 (6건)"처럼 결과를 바로 보여준다.
- **할부 총액 입력** (결정): 총액을 회차로 나누고, 나누어떨어지지 않는 끝전은 첫 회에 더한다.

| 화면 | 제안 | 결정 |
|---|---|---|
| 월간 달력 | 좌우 스와이프로 월 이동 | MVP 포함. 손가락을 따라 움직이는 방식 (4-2) |
| 월간 달력 | 칸이 좁을 때만 금액 줄여 표시 | MVP 포함 (4-2) |
